**Unslop agent prose.** Use short sentences. When writing docs, READMEs, or skills, pair the `unslop` skill with [Sloptrim](https://github.com/seyedehsanhadi/sloptrim). Use `unslop` to revise prose, then run Sloptrim before the files leave the repo.

**Guard the context.** When subagents are available, delegate bulk exploration and reviews. Handle trivial tasks in the main thread. Give each agent a clear question, scope, relevant files, and constraints. For reviews, include the review base and spec. Ask for concise findings with file and line evidence and checks run. Keep summaries and decisions in the main thread. Leave bulk reads and logs with the subagents.

**Choose the Herdr server.** Standalone `herdr` and Herdr App/core use separate servers. For the terminal TUI, use the installed `herdr` skill and CLI with `HERDR_ENV=1`. For App window changes, read `herdr-app --skill`; for its terminals and agents, read `hc --skill`. Core identifies its caller with `HC_TERMINAL_ID`. Use App/core only when requested or when the verified caller is a core terminal. Use the requested backend and keep IDs scoped to its server and machine. Inherited markers alone do not prove caller identity. Resolve an unclear backend or caller before changing panes. Never retry a missing target on the other server.

**Orchestrate external agents.** Requests such as "ask Codex" or "discuss this with Pi" authorize launching that agent. Use the requested model and harness. For App/core, follow `hc --skill`, including interactive agents and Codex `--no-daemon`. Elsewhere, for reviews, second opinions, or results to parse, prefer the harness's native headless CLI. For headless runs, send the prompt on stdin and save the final response and exit status in fresh files. Check for exit code 0 and substantive text ending with the requested marker, such as `REVIEW_COMPLETE`, before accepting a headless result. Read the result and report the findings here. If the requested agent is unavailable, explain the blocker.

**Isolate Codex reviews.** On both `codex exec` and `codex exec resume`, pass `--ignore-user-config --ignore-rules -c 'approval_policy="never"' -c 'model_reasoning_effort="high"'`. Honor any requested reasoning effort instead. Use `--sandbox read-only -C <repo> -o <result> --color never - < <prompt>` for the first turn. Keep the session ID and omit `--ephemeral` for follow-ups. Resume that exact ID from the same directory with `-c 'sandbox_mode="read-only"' -o <new-result> <session-id> - < <next-prompt>`. Resume has no `--sandbox` or `-C` flag. Pass the requested model explicitly with `-m`.

**Use Herdr for display.** With standalone terminal Herdr selected and `HERDR_ENV=1`, use the `herdr` skill to run headless work as an ordinary process in a new sibling pane. Preserve the current directory and user focus. Have the script record its exit code; use `set -o pipefail` with `tee`. Read result files. Interactive `agent start` and `agent prompt` suit open discussion with the user watching.

**Start reviews fresh.** Run each external review in a new session and a new pane or core terminal. Never reuse a terminal or session that holds context from earlier work. Reuse one only to continue the same topic, such as discussing its findings.

**Keep Herdr context.** Identify targets by returned IDs or known agent identities. Labels and focus can change. Pass new agents the selected backend, its returned IDs and working directory. Reuse context within the same server and machine. Follow that backend's installed manual for commands, caller resolution, and lifecycle handling. If caller identity remains unclear, ask before changing panes.
