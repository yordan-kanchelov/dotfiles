# T3 Inbox

A sidebar for Herdr App that keeps only the agents still asking for your attention in sight, as cards, newest news first. Agents you are done with are settled by hand and sink into a quiet, folded list at the bottom; any new work brings them back. Modeled on the Settle sidebar of [T3 Code](https://github.com/pingdotgg/t3code).

![T3 Inbox](preview.png)

## What you see

Top to bottom, on the `chrome` theme background, 13px text:

1. **Top row** (32px, left padding 8, right 10): a wide `Search` button (32px high as T3's search field, 16px search icon + "Search", 14px medium), then three 26px square icon buttons: space filter (`list-filter.svg`, or the chosen space's mark, two overlapping marks when several), New space (`folder-plus`), New tab (`square-pen`).
2. **Cards** (scrolling list, padding 8, gap 2): one per agent that isn't settled and isn't working. Card: padding 10/6, radius 6, as T3's, `selected` background when it is the focused agent, `hover` background otherwise on hover.
   - Line 1 (20px, 12px `dim` text): the space's 16px mark (below), space name, then the corner.
   - Line 2: title at 14px. As T3's, it leads (`foreground`, medium) when focused, blocked or done, else recedes (`muted`, normal); hovering brightens it, in color only.
   - Line 3, only when there is something to say (12px `dim`): branch, and "N sub-agents working".
   - Marks: the 16px program icon at 60% opacity, after a 14px `dim` server mark for an agent on another machine, naming the machine on hover. They end line 3 when the card has one, else line 2, so the title keeps its line.
   - Corner: `Needs you` (amber `blocked`, a 14px `!` badge) for blocked, `Done` (green `ansi2`, circle-check) for done and not yet seen, else how long ago it last changed (`just now`, `5m`, `3h`, `2d`, as T3: no weeks).
   - Empty: "Nothing needs you." (or "No agent status yet…" when no agent has reported).
3. **Shelves**, pushed to the bottom by `margin-top: auto`:
   - **Working N** header (32px as T3's, 12px medium `dim`, a regular-weight count and the chevron at the right), folded by default; open, it lists working agents as cards with a spinner pill `Working 9s` counting up (`4m`, then `1h 5m`), at 70% opacity until hovered or focused.
   - **Settled N** header, folded by default; open, it shows the 10 most recently settled as slim rows, then `Show 25 more`. A `Clear` button before the count closes the settled panes (not the one in view or its tab), after asking through the shipped `confirm` dialog (`Close N terminals?`, as closing a tab asks; its command is `t3-inbox.clear`). Herdr closes emptied tabs. Spaces stay: one left empty first gets a shell tab where its terminals were (`panes().cwd`, not the space's starting folder, which would rename an unnamed space) (`tab.new`; `pane.close` refuses a space's last pane), then the view returns to the tab you were on. Sessions stay with the agent (`pi -r`, `claude -r`, `codex resume`).
   - Slim row: 36px as T3's, radius 6, led by the space's 16px mark at 40% opacity until focused or hovered, then a `muted` title and the settled-ago time at the right.

**Space marks**, as T3 Code draws a project (`mods/t3-inbox/project.js`): the project's own icon (radius 25%), looked for from the repo top of where the space is now (its first terminal's folder, else where it was made): T3's well-known files in order (`favicon.svg`, `public/favicon.ico`, … `.idea/icon.svg`), then a page's `<link rel="icon">` or a route's `{ rel: "icon", href }`. Found, it is copied to `cache/t3-icons/` in the app's folder, since images show only from there, and shared as `space.icons`; looked for again after 10 minutes, a missing one after a minute. Else a monogram: the name's first letter or digit, capitalized (`智能算量` → `智`), bold monospace at 0.64 of the mark, in one of T3's 18 colors hashed from the name on a 14% wash of it. A name with nothing to spell (`~`) shows a folder.

## How it behaves

- **Statuses.** `blocked`, or `error` (a failed turn, its own or a sub-agent's, read from `terminals()` since `agents()` has no such word) shows Needs you and stays up top. Next, its own `done`: its reply shows Done in Active, with its working sub-agents beside it, and once read it goes back to Working with the run's start. `working`, or an agent waiting on a working sub-agent, goes to the Working shelf. `idle` shows its age. The rule is `mods/t3-inbox/tree.js`, shared with Herdr T3.
- **Order.** Cards by when each last came back to you (a state change this mod saw; before that, the core's `status_ms`). Working by when its run started. Settled by when it was settled. Equal times go by address, so the order never follows the order the data came in. Looking at a card moves nothing. A run that stops stays on the Working shelf for 2s, as in T3, showing its real state meanwhile: going on within that keeps its place, and so does a pause for you (blocked) followed by more work; after it, the card lands on top of the cards. Blocked leaves at once; pinned and settled agents skip the grace. An agent missing from the list for a moment keeps its place; only ended terminals lose their record. The order is passed to `setAgentOrder`, settled agents last, so `agent.next` / `agent.prev` follow the list as it reads.
- **Click** a card or slim row: `agent.focus` on it (focuses its pane; in a layout with an agent block, shows it there). Viewing a settled agent leaves it settled.
- **Settle.** Hovering a card that is finished (nothing in its tree working or blocked) turns its corner into a `✓ Settle` button, a pinned one too. As T3's, Settle drops the pin at once. If the write fails, the pin goes back to its old place, and pins made meanwhile stay. Undo also puts the pin back in its place. Settling the focused agent moves focus to the next card down, wrapping from the top past the end, as T3; settling one in the background moves nothing. The key command `t3-inbox.settle` does the same for the agent in view (finished), or brings it back to the top of the cards if it is settled. The Settle button's hover label names the settle key only on the card in view, the one the key acts on, and so does the undo arrow of the settled row in view.
- **Un-settle.** Hovering a slim row turns its time into an undo arrow (label `Un-settle`); clicking puts the agent back at the top of the cards. Only explicit returns go on top: this arrow, a drag out of Settled, and the key on a settled agent. Undo puts the agent back where it was. A `settled` label cleared any other way, such as Undo in another window, also keeps its old place. Herdr T3's tab bar reports its own key's returns in `shared("t3-inbox.unsettled")` (address → a stamp that grows with each return), and the Inbox takes each new stamp as one return.
- **Undo notice**, as T3's: Settle and Unpin show `Settled 2 agents, Undo` over the first shelf's header for 5s (200ms fade). A run of the same action counts together; Undo puts them back as they were, not as news. No key: ⌘Z belongs to the terminals.
- **Row details**, as T3's thread card: hovering a card or slim row hangs a `Popup` 4px to its right, from its top: the title, then its space, another machine's name, branch and program, 12px, 320px at most. 150ms to the first; while one is up or was under 400ms ago, the next opens at once. The first and the last fade over 150ms. A control lit in the row, a drag or a click on the row hides it.
- **Keyboard**, as T3's focus-visible (`focus.js`): `pane.go` onto the Inbox (`"focusable": true`) starts a keyboard mode in which Tab walks its controls with a 2px inset `accent` ring, a card's hover-only controls show while the keyboard is on it, and Enter or Space acts. Menus take Home and End, and those without a search field T3's typeahead; a search field keeps Home and End for its caret. The keyboard leaving every control ends the mode; with the mouse nothing changes.
- **Hover labels**, as T3's tooltips: every icon-only control and wordless mark names itself with a `HoverCard` (`tip.js`), with its bound key where it has one. A program's icon has none.
- **Motion**, as T3's: when rows change order or section, each that moved slides from where it was (the shelves' headers, Show more and the empty line too, so a row never slides over one), a new one fades in from 40px up or riding with the kept row above it, one that left fades out where it was; 150ms ease-out, none while dragging or for more than 40 rows at once. A dropped row slides from where it was let go. Hovering a row cross-fades its time with its Settle or undo button.
- **Drag.** As in T3: move a card or row 6px to lift it. While lifted, the `Pinned` and `Active` labels open, the lifted copy follows the pointer up and down and says what letting go does (`Pin`, `Unpin`, `Settle`, `Un-settle`), and the list opens a gap the size of the destination's row where it will land (a native 150ms `height` transition); empty or folded sections show a dashed placeholder. Onto Pinned pins (upper or lower half of a pin: above or below it), onto Active unpins and unsettles, onto Settled settles. Esc or leaving the sidebar sideways puts it back; leaving off the top or bottom lands it where the badge says (Herdr reports no release outside the sidebar); Working cards don't lift. Sweep: press `✓ Settle` or a settled row's undo and move across rows to settle or bring back the whole run. Pinned cards stay up top in pin order. Pins live in shared state `agents.pins`, the same list Herdr T3's agents list uses.
- **New work unsettles by itself:** the agent (or a sub-agent) becomes working or blocked, or the core's `turn` counter has passed the one stored at settle time, which also catches work done while no window was open.
- **Filter.** The filter button opens a popover (260px wide, at most 360 tall) with a search field and `All spaces` plus every space. Click shows that space alone; shift-click adds or removes it and keeps the menu open. Remembered on this screen.
- **Search** opens the mod named by the `picker` prop, else the shipped `picker`; **New space** runs `space.new`; **New tab** opens the mod named by the `newMenu` prop, else the shipped `new-menu`.
- **The row in view**, as T3's route row: it stays out of a folded shelf and past the Settled page; a sub-agent in view with no row of its own lights its nearest listed ancestor, and Settle acts on that card; an agent brought into view from elsewhere that the filter hides widens the filter to all spaces, kept (not on the first draw, and a filter picked while it's in view holds).
- **Snooze**, as T3's: `snoozed=<wake ms>` on the agent's terminal (`hc label`, kept pending until it comes back). Hovered, any card not needing the person (working and pinned ones too; a failed turn counts as needing them) shows a 20px `clock` button before Settle; hovered controls take the corner's slot and the state fades out from under them. It opens a menu (`Popover`, fading in over 150ms, as wide as its rows and 160px at least, 28px rows, hanging from the clock's left edge and out over the sidebar's; nothing lit until the pointer or a key gets there; ↑/↓, Enter or Space, Esc; the panel takes the focus handle, and Enter and Space are bound on open in its own key context, as the Popover's own would only close it): In 1 hour, In 3 hours, This evening (6 PM, until it's past), Tomorrow (9 AM), Next week (Monday 9 AM; a Sunday reads Tomorrow), soonest first, one row per wake minute, with the wake time at the right. As T3's, a duration counts from the click and a time that has passed since the menu was drawn is refused with a warning. Under a separator, `Custom…` opens a dialog (this mod as an overlay, as t3-actions' editor): Date and time (a drawn calendar, days gone by not pickable, and `HH:MM`) or Duration (an amount in a number field with − and +, and Minutes, Hours or Days from a select, as T3's). What can't be, a time that doesn't exist or has passed or a duration that isn't positive, says so and stays open; the answer goes to the inbox through `shared("t3-inbox.custom")` and the `t3-inbox.custom-snooze` command, and snoozes as a preset does, unless by then the agent needs the person. No configurable presets. Snoozing leaves T3's `Snoozed 1 agent, Undo` notice and, if in view, moves on as Settle does. The Snoozed shelf sits between Working and Settled, folded, soonest back first, its rows as settled ones with the time left (`10m`, `3h`, `2d`, an `accent` alarm clock) that hover swaps for a crossed-out alarm clock (Wake; press and move across rows to wake the run). Drag a row out to wake it (badge `Wake`); nothing drags in: a drop can't say when. Due, it wakes where it was (`track` skips the grace meanwhile; a run that ended under snooze has come back to the person, so it wakes on top, as T3's return does), marked `Woke` in `blocked` until viewed or clicked (viewing counts only in the active window: one in the background clears no due snooze, nor a new turn's, so Woke waits for the person); Woke stays beside the controls on hover, and shows beside `Working` for one still at work. Undoing a Settle brings back a snooze that hasn't run out. Early: needing the person shows it for as long as that lasts (the label stays); a failure in its tree, a new turn in view, Wake, a pin or Settle clears the label. Pinned, it keeps its pin underneath and wakes back to it.
- **Mod pane cards.** No agent's card leads to a mod pane in a tab with no agent, so one whose mod asks with `inbox: true` in `shared("<mod>.program")` (a review: `{ icon, tint, name, inbox: true }`; an icon alone doesn't ask) has a card of its own, one per tab: its space's mark and name, its `<mod>.titles` name, its icon where an agent's program goes. It goes by `<mod>.status` as an agent by its status: `working` on the Working shelf, `done` and `blocked` back on top of Active; first seen, on top of Active. `inbox: true` also says the pane can go at any time, its state living elsewhere: Settle (`Settle and close`, offered as for an agent, and `cmd-shift-s`) is `pane.close`, moving on first if it's in view, with no Settled and no Undo; the last tab of a space asks first. A click is `pane.focus`, across spaces. No pin, no drag, not swept. The space filter applies, and bringing one into view widens it. A mod pane beside an agent has no card: it lights that agent's.
- Shelf folding, the filter and the last seen states are kept in the mod's `localStorage`. The rows as drawn are shared as `t3-inbox.rows` (`{ order, view }`), for a layout's keys to walk them: an agent's address, or `pane:<id>` for a mod pane's card, which takes `pane.focus`.

## Watch out

- A label written with `hc label` takes about 0.65s to come back in `terminals()`. Keep the new value as pending so the row moves at once; drop it on failure and show an error `notify`. On a slow remote, writes to one label can land in any order: while more than one is out, keep the last intent and, once all have answered, write it again if the label says otherwise.
- `terminals()[].status_ms` is only as of the app's start; it is a fallback until the mod sees a change itself.
- Treat `done` and `idle` as one when tracking change times: looking at a done agent turns it idle, and looking is not news.
- Sub-agents without a pane aren't in `agents()`; walk `terminals()` by `parent` for them.
- A card moves away without a pointer-leave event: clear the hover state on Settle / Un-settle.
- A hover style reaches text but not an `svg`; keep hover as state so icon and label brighten together.
- Herdr eases only later changes to an element: a row that moves gets a new id, is drawn once where it was, then let go.
- Herdr can't scroll a plain list from code, so unlike T3 the row in view isn't scrolled into view.
- `.tooltip()` takes only a string in the shell's own style, hence a `HoverCard`; it doesn't flip, so what sits at the window's bottom must open upward itself. The details card is solid: T3's glass blurs what's behind it, and a mod can't.
- No auto-settle. Settling never touches the process.

## Done when

- `herdr-app check mods/t3-inbox` passes.
- A finished agent shows `✓ Settle` on hover; clicking moves it to Settled within a second and `hc get <address> --json` shows `settled=<ms>:<turn>`.
- That Settle shows `Settled 1 agent, Undo` for 5s; Undo puts it back as it was.
- Snoozing a working agent for 1 hour moves it to Snoozed; a permission prompt shows it as Needs you, and answering it hides it again. Due, it wakes marked `Woke`.
- Hovering a card fades its details in beside it; moving to the next card shows that one's at once.
- `Clear` asks through the `confirm` dialog before it closes anything.
- Sending that agent a new prompt brings it back to the cards and removes the label.
- Hovering a settled row and clicking the arrow puts it on top of the cards.
- With 11+ settled agents, the open shelf shows 10 and `Show N more`.
- `agent.next` walks the cards in their shown order.
