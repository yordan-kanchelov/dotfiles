# Delete comments

This repository bans code comments ([ADR 0001](../../../docs/adr/0001-no-code-comments.md)). `scripts/check-comments.py` is the ratchet. `scripts/comment-baseline.json` holds the per-file allowance, which can only go down. This skill runs the triage that lowers it.

Scope is `$ARGUMENTS` if given, else the whole repository. The scanner already skips pinned upstream payloads (`agent-setup/*/sources.json`), vendored themes, licences, lock files and `files/secrets.template`. Do not edit those files to make a comment go away.

## 1. Inventory

```bash
python3 scripts/check-comments.py --list $ARGUMENTS
```

Read each comment together with the code around it. Treat consecutive comment lines as one block. Keep the listing (for example in your scratchpad), because line numbers change once you start editing.

## 2. Check that each hit is really a comment

Some `#`, `--` and `//` lines are not comments. Leave them alone, and fix the scanner if it miscounted:

- **Directives** that tools read: shebangs, `# shellcheck`, `# noqa`, `#Requires`, modelines, type pragmas, Lua `---@` annotations, Yazi's `--- @sync entry`. When you find a new one, add it to `DIRECTIVES` in `scripts/check-comments.py`, with a fixture in `scripts/test-check-comments.py`.
- **Content**: text written into a generated file, such as a config template or a heredoc that produces user-facing text. Move it into a file of its own (as `files/secrets.template` was), so the code no longer holds it.
- **Scanner false positives**: string contents, URL fragments, colours, zsh glob flags such as `(#q...)`. Fix the tokenizer and add a fixture.

## 3. Classify

Put every block into exactly one category:

| Category | Test | Action |
| --- | --- | --- |
| Tautology | The code, a name, or `--help`/`brew info` already says it. Section banners, package descriptions, "Pane navigation" above pane bindings. | Delete. |
| Stale | It refers to something that is gone or no longer true: commented-out code, template boilerplate ("Add any additional options here"), installer provenance markers, paths or tools that have since been replaced. | Delete. |
| Excuse | It justifies a shortcut instead of fixing it: `\|\| true` "because the real check is later", a fixed `sleep`, "assumes X", "copied from Y", `ponytail:` markers, a check that cannot fail, a workaround repeated in several files. | Delete, and file an issue. |
| Decision Record | It explains a non-obvious *why* that the code cannot show: a platform quirk, a measured number, an ordering constraint, a rejected alternative, a safety rule. | Move it into an ADR. |

When a block mixes categories, split it: the *why* goes to the ADR and the excuse gets an issue.

## 4. Act

**Decision Records.** Find the ADR for the area in `docs/adr/README.md` and add a bullet under the right heading, naming the file it applies to. Write a new `docs/adr/NNNN-<topic>.md` only when no area fits, using the same Status / Context / Decision / Consequences layout, and add it to the index. Check each claim against the code before you write it down, because a comment can be wrong. Write plain, specific prose, with the measured numbers and the rejected alternative.

**Excuses.** First list the open issues, to avoid duplicates. Then file one issue for each distinct workaround, not one per comment line; one issue can cover the same workaround found in several files. Use this body:

```markdown
Found during the comment triage (`docs/adr/0001-no-code-comments.md`). The comment that excused this has been removed. The rationale is now in `docs/adr/NNNN-....md`.

**Where:** `path`, task or function name

**What the removed comment excused**
> the original comment, quoted

Why it is a problem.

**Suggested fix**
A concrete fix.

---
_Generated by [Claude Code](https://claude.ai/code)_
```

Link the issue from the ADR bullet that describes the area (`[owner/repo#N](https://github.com/owner/repo/issues/N)`).

## 5. Strip

```bash
python3 scripts/check-comments.py --strip <paths>
```

This deletes full-line comments and trailing comments, and collapses blank lines left behind by deleted blocks. Review `git diff`. Remove anything that now reads oddly, and make sure no code line changed beyond losing its trailing comment.

It is fine to leave some comments for a later run, for example when you could not verify an ADR claim. Strip only the files you finished.

## 6. Verify

Run whatever covers the files you touched:

```bash
python3 scripts/check-comments.py --update
python3 scripts/check-comments.py
python3 scripts/test-check-comments.py
ansible-playbook setup.yml --syntax-check
ansible-lint
zsh -n zsh/.zshrc zsh/.zshrc.core zsh/.zprofile
bash scripts/test-agent-config.sh
```

Also run `bash -n` or `shellcheck -S error` on changed shell scripts, `python3 -m py_compile` on changed Python, `node --check` and `node --test agent-setup/herdr-app/local-mods/prefix.test.mjs` for the Herdr mod, and the `scripts/test-*.sh` and `windows/test-*.ps1` that cover the changed files. `--update` only lowers allowances. If it refuses, a file gained comments: go back to step 3.

## 7. Report

Give the number of blocks and lines in each category, the issues filed (as links), the ADRs added or changed, and the lines shed (`git diff --shortstat`). Also list anything you left in place, with the reason.
