# Context tool evaluation

Assessed on 2026-10-28 for this repo's Claude Code and Codex setup, including skills, MCP tools, parallel exploration, and long coding sessions. Billing and login methods were not confirmed. These recommendations distinguish subscription access from metered API use.

Headroom is the strongest candidate for a limited trial. Distillery is a simpler option for repetitive Claude/API traffic. Billion-context has useful long-session mechanisms, but its default behavior rules out adopting it in the shared setup.

All three reduce the context sent to a model. Their emphasis differs. They do not increase its actual attention window, and retaining originals does not guarantee that a model will retrieve an omitted detail.

| Tool | Main purpose | Advantages for us | Main costs |
| --- | --- | --- | --- |
| Distillery | Deduplicate tool results, distil large outputs, and trim history through a local proxy. | Simple Node packaging and a free basic tier. | Limited Codex login support, metadata collection, and another routing dependency. |
| Billion-context | Keep a long conversation usable with hierarchical summaries and restoration tools. | Searchable originals and explicit control over compression. | Changes native compaction, intercepts transport, and enables a Claude safety-classifier bypass by default. |
| Headroom | Compress tool output by content type, with retrieval of originals. | Fits noisy MCP, logs, JSON, and exploration across Claude/Codex. Offers optional shared memory. | Python runtime, wrapper behavior changes, local content caches, and optional features to disable during a trial. |

The project descriptions establish these mechanisms. [Distillery](https://thedistillery.dev/), [billion-context](https://github.com/ranxianglei/billion-context), [Headroom](https://github.com/headroomlabs-ai/headroom).

Distillery has free deduplication and tool-output distillation. Pro costs EUR 9 per month. Its repository identifies Elastic License 2.0. It is source-available with restrictions that differ from MIT or Apache licensing. Its setup guide claims Claude OAuth support, but explicitly requires API-key login for Codex. Do not switch subscription usage to metered API calls just to use it. [Pricing](https://thedistillery.dev/pricing/), [repository](https://github.com/The-Distillery-dev/thedistillery), [client setup](https://thedistillery.dev/for-agents/).

Distillery says compression stays local. Its privacy policy also lists uploaded usage metadata, session identifiers, and project directory paths. Paths can disclose customer or project names. Its documented benchmark uses five fixtures, estimated token counts, and no model calls. That measures payload reduction without establishing preserved coding quality or lower bills. [Privacy policy](https://thedistillery.dev/privacy/), [benchmark method](https://thedistillery.dev/benchmark/), [benchmark walkthrough](https://thedistillery.dev/blog/how-to-benchmark-claude-code-token-savings/).

Billion-context lets the model compress older history and later decompress or search it. Its Claude integration disables native auto-compaction. Current Codex subscription guidance uses an HTTPS interception proxy and a generated CA through its launcher. The Codex MCP plugin alone does not route model traffic or provide compression. [Client integrations](https://github.com/ranxianglei/billion-context/blob/master/CLIENTS.md).

Billion-context's `autoModeForge.enabled` defaults to true, including in release v0.1.208. It recognizes Claude Code auto-mode classifier requests and responds locally with an allow verdict. This affects that classifier, not Codex approvals or every Claude permission check. It can be disabled with `BILI_AUTO_MODE_FORGE=0`. A context tool changing this behavior by default is enough reason to reject the default installation for us. [Versioned default](https://github.com/ranxianglei/billion-context/blob/v0.1.208/src/knobs.ts#L223), [classifier implementation](https://github.com/ranxianglei/billion-context/blob/master/src/auto-mode-forge.ts).

Billion-context also retains session content and enables automatic updates. Its package declares MIT, while the license includes an additional product-attribution requirement. Its paper labels the headline 5.3x saving a modeled counterfactual for a marathon session. It also reports that tested models did not spontaneously use restoration, though they could restore content when instructed. These findings limit confidence in unattended recovery. [Configuration](https://github.com/ranxianglei/billion-context/blob/master/CONFIGURATION.md), [license](https://github.com/ranxianglei/billion-context/blob/master/LICENSE), [paper](https://github.com/ranxianglei/billion-context/blob/master/paper/model-driven-incremental-hierarchical-compression-training-free-multi-generational-context-management-for-long-lived-coding-agents.md).

Headroom supports local proxy, SDK, wrapper, and MCP modes. Its code handles Codex ChatGPT authentication, and its docs describe Claude subscription and API authentication. Those are intended integration paths, not verified compatibility with our accounts. The MCP interface alone should not be treated as automatic compression of all native tool traffic. [Codex implementation](https://github.com/headroomlabs-ai/headroom/blob/main/headroom/providers/codex/install.py), [proxy guide](https://docs.headroomlabs.ai/docs/proxy), [troubleshooting](https://docs.headroomlabs.ai/docs/troubleshooting).

Headroom uses Apache 2.0. Its CLI comes from the Python package; npm supplies the TypeScript SDK. Its wrapper adds Serena unless disabled with `--code-memory none`. A custom Claude endpoint has documented compatibility costs, including unavailable Remote Control. The Codex wrapper also changes background-server behavior. [Repository](https://github.com/headroomlabs-ai/headroom), [wrapper code](https://github.com/headroomlabs-ai/headroom/blob/main/headroom/cli/wrap.py), [troubleshooting](https://docs.headroomlabs.ai/docs/troubleshooting), [proxy guide](https://docs.headroomlabs.ai/docs/proxy).

Headroom stores recoverable originals in a plaintext local cache by default. Its content-free usage beacon is enabled by default and can be disabled with `HEADROOM_BEACON=off`. Optional memory adds more persisted state. Keep it outside the versioned dotfiles bundle and review retention before using customer repositories. [Security policy](https://github.com/headroomlabs-ai/headroom/blob/main/SECURITY.md), [security model](https://docs.headroomlabs.ai/docs/security-model), [recovery design](https://docs.headroomlabs.ai/docs/ccr).

Raw token savings are an incomplete score. Rewriting history can reduce cache reuse; summarization, retrieval, and retries can consume the saving. OpenAI's official documentation explains that prefix matching depends on unchanged context. Subscription fees also do not fall in proportion to compressed requests, and quota effects require measurement. [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching), [Codex authentication](https://learn.chatgpt.com/docs/auth).

An older, competitor-published July 4 experiment reported Headroom solving 58 of 100 tasks versus 57 without compression, but costing 44% more overall. The publisher also owns competing product Parsec. Headroom merged cache fixes after that run. This is a historical example of why completed-task cost matters, not a verdict on current Headroom. [Experiment](https://github.com/daseinlabs/code-compression-bench), [publisher](https://github.com/daseinlabs), [fix](https://github.com/headroomlabs-ai/headroom/pull/1850), [follow-up](https://github.com/headroomlabs-ai/headroom/pull/1852).

For our setup, keep native sessions as the baseline. First reduce avoidable output and redundant skill loading. A proxy will not resolve conflicting instructions or excessive mandatory workflows. The existing setup already advises keeping full meta-skill bodies out of always-on instructions. [Claude setup](../../agent-setup/claude/README.md), [Codex setup](../../agent-setup/codex/README.md).

Trial Headroom on tool-heavy exploration, a noisy test failure, and a task that crosses compaction. Disable extra memory, learning, output shaping, Serena, and telemetry for the initial comparison. Use matched tasks with the same model. Measure successful completion, elapsed time, retries, missing constraints, cache-adjusted API cost, and subscription usage where visible. Keep it only if it improves those outcomes. Do not stack compression proxies or add one to bootstrap before that comparison.

No tools were installed and no account traffic was intercepted. This assessment covers documentation and selected source inspection. Actual savings, runtime compatibility, and complete security behavior remain untested.
